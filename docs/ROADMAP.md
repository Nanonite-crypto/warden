# Roadmap

Warden is built in phases. Each phase ends with something that can be run
and tested, and no phase starts before the previous one is accepted.

| # | Phase | Ends with | Status |
|---|---|---|---|
| 1 | Engine core + hash matching | `warden scan <folder>` finds EICAR by hash and prints a report; tests pass in CI; first files/sec and MB/sec numbers | Built, awaiting acceptance |
| 2 | YARA layer + zip scanning | The same command catches an EICAR variant whose hash is not in the database, and EICAR inside a zip; the rule bundle builds from YARA Forge; first false-positive run over System32 | |
| 3 | PE heuristics | `warden inspect <file>` explains a score indicator by indicator; calibration report against EMBER2024; fuzzers running | |
| 4 | Quarantine | `warden quarantine add / list / restore / delete` round-trips a test file with hash, timestamps and permissions intact, including a simulated crash mid-operation | |
| 5 | Persistence remediation | In a VM: a harmless dummy program registered as a test threat, with a Run key, task, service and startup shortcut pointing at it. One command removes all four; restore brings them back | |
| 6 | Service + IPC + scheduled scans | The service is installed; a standard-user terminal drives a scan through the pipe with live progress and cancel; history, settings, exclusions and schedules survive a reboot | |
| 7 | Desktop app | The full flow in the GUI: scan, detection with reasons, quarantine, restore; schedule settings; tray icon, notifications, installer | |
| 8 | Portfolio checkpoint | README with architecture diagram, screenshots and engine explanation; benchmarks regenerated by one command, with ClamAV as a reference point; EICAR demo recording; a tagged release that installs on a clean VM; the repository goes public | |
| 9 | Real-time protection (user mode) | Drop EICAR into Downloads: notification and automatic quarantine; an alert when a new autostart entry appears; measured time-to-detect | |
| 10 | Self-protection | A tamper script where every attempt fails as a standard user; a documented table of what succeeds as administrator; THREAT_MODEL.md | |
| 11* | ML classifier | `warden inspect` shows a model score; ROC curve on the EMBER2024 test period against the heuristic layer | |
| 12* | Kernel-assisted real-time | VM only, test-signed: opening EICAR is blocked before it can run | |
| 13* | AMSI provider | Script content (PowerShell, Office macros) is scanned before it runs | |

\* Optional. Phase 13 comes last, only after everything else is solid.

Phases 1 to 8 deliver every portfolio deliverable. Phases 9 and 10 add the
systems depth.

## Decisions

| Date | Decision |
|---|---|
| 2026-11-18 | Name: Warden. Engine and core logic in Rust; desktop app in Tauri with React and TypeScript. |
| 2026-11-18 | Detection layers in order: hash matching, YARA rules, PE heuristics, then an optional ML classifier. |
| 2026-11-18 | No live malware, ever: not written, generated, modified or handled. Tests use the EICAR file, inert fixtures and public feature data. Detection rates on live samples are therefore reported as not measured, and the README says why. |
| 2026-11-18 | In scope beyond the original brief: zip scanning with limits on nesting depth, unpacked size, member count and compression ratio (phase 2); scheduled scans (phases 6 and 7); ClamAV as a benchmark reference (phase 8); an alert on new autostart entries (phase 9); an AMSI provider as the last optional phase. |
| 2026-11-18 | The repository is private until the portfolio checkpoint (phase 8). |
| 2026-11-18 | Real-time protection starts in user mode. A kernel minifilter is a late, optional, VM-only phase, because distributing a driver needs Microsoft's signature. |

## Open decisions

- **Licence.** None chosen yet; needed before the repository goes public.
- **MalwareBazaar import with family names.** The plain hash-list import
  exists. Importing the CSV export, which carries malware family names,
  waits until it can be tested against a real export, which needs a free
  abuse.ch Auth-Key.
- **Windows endpoint security platform.** Microsoft announced general
  availability in November 2026. Whether a non-partner can use it is not
  documented publicly yet; to be checked before phase 12.
